# AgroTechCare

Бэкенд мобильного приложения для сервисного центра сельхозтехники: клиенты отслеживают ремонт своей техники, механики принимают и закрывают заказ-наряды, а учётная система компании (1С) получает данные через интеграцию.

## Зачем этот проект

Проект вырос из реальной задачи. Компания, которая продаёт, ремонтирует и выпускает сельхозтехнику и ведёт учёт в 1С, заказала мобильное приложение для клиентов и механиков. Бэкенд тогда писала другая команда, а я — интеграцию со стороны 1С: запросы к их API, хранение сырых ответов и фоновую обработку с повтором при ошибках.

Здесь я пишу этот бэкенд сам — на Java и Spring Boot, с нуля и по шагам. Данные и названия вымышлены.

**Что умеет система (целевое состояние):**

- **Клиент** видит свою технику и договоры, создаёт заявку на ремонт, следит за статусом, работами и стоимостью.
- **Механик** принимает заказ-наряды, фиксирует выполненные работы и израсходованные запчасти.
- **Менеджер** распределяет заявки между механиками и контролирует сроки.
- **Интеграция с 1С** — обмен справочниками и документами через очередь сообщений с гарантией доставки (Transactional Outbox / Inbox).

## Стек

- Java 21, Spring Boot 3.5 (Web, Data JPA, Validation)
- PostgreSQL 17, Flyway
- Docker Compose
- Maven, Lombok, MapStruct

## Запуск локально

**Нужно установить:** JDK 21, Maven, Docker.

1. Скопировать пример настроек и при необходимости поменять значения:

   ```bash
   cp .env.example .env
   ```

2. Поднять PostgreSQL:

   ```bash
   docker compose up -d
   ```

   База будет доступна на `localhost:45432`.

3. Запустить приложение — из IntelliJ IDEA (класс `AgroTechCareApplication`) или командой:

   ```bash
   mvn spring-boot:run
   ```

   Приложение само прочитает `.env` из корня проекта, а Flyway при старте применит миграции.

Остановить базу: `docker compose down`. Данные сохраняются в Docker volume; удалить их вместе с контейнером — `docker compose down -v`.
