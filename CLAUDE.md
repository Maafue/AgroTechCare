# AgroTechCare — правила проекта

Бэкенд мобильного приложения сервисного центра сельхозтехники (клиенты, механики,
менеджеры) + интеграция с 1С. Пишем как продакшен-сервис команды, а не как учебный CRUD.
Модель данных и решения по ней — `docs/er-model.md`, это источник правды.

## Роли в работе

- Весь backend-код пишет автор. Claude не пишет backend-код: даёт задачи (Issues),
  подсказки, объяснения и делает ревью. Claude отвечает за `docs/` и frontend.
- Объясняя, проводи аналогии с 1С, где это помогает.
- Каждое Issue содержит раздел «📚 Теория к задаче» — рекомендация, не блокер.

## Git

- GitHub Flow: защищённый `main`, ветка `<type>/<issue#>-<slug>`, PR с `Closes #N`.
  Типы: feature, fix, chore, refactor, docs, test.
- Conventional Commits на английском: `feat(work-order): add status transitions`.
- Команды, меняющие состояние git в рабочей копии, автор выполняет сам.

## Структура пакетов — по фичам

Корневой пакет `by.morozmaksim.AgroTechCare`. Внутри — пакет на каждую фичу,
в нём всё, что к ней относится (аналог подсистемы в 1С):

```
workorder/
  WorkOrder.java              сущность
  WorkOrderStatus.java        перечисление
  WorkOrderRepository.java
  WorkOrderService.java
  WorkOrderController.java
  dto/                        запросы и ответы API
  mapper/                     MapStruct
common/                       общее: обработка ошибок, базовые классы, конфигурация
```

- Фичи по ER-модели: `client`, `user`, `machine` (бренды, модели, машины),
  `contract`, `workorder`, `catalog` (работы, запчасти). Новые — по мере появления.
- Фича обращается к другой через её сервис, а не напрямую к чужому репозиторию.

## API (потребитель — мобильное приложение)

- REST, префикс `/api/v1`. Ломающие изменения контракта — только в новой версии:
  старые версии приложения живут у пользователей неделями.
- Наружу — только DTO (`record`), сущности JPA из контроллера не возвращаются.
- Валидация входа — Bean Validation на DTO (`@Valid`), бизнес-правила — в сервисе.
- Ошибки — единый формат `ProblemDetail` (RFC 9457) через `@RestControllerAdvice`
  в `common`; стектрейсы и SQL наружу не уходят.
- Списки — всегда с пагинацией.
- Время — `Instant`/`OffsetDateTime`, в JSON ISO-8601 с зоной; в БД `timestamptz`.
- OpenAPI (springdoc) подключаем после того, как готовы контроллеры и тесты к ним.

## Слои

- controller → service → repository. `@Transactional` — на сервисе,
  чтение — `readOnly = true`. Внутри транзакции нет внешних HTTP-вызовов.
- Маппинг Entity ↔ DTO — MapStruct.
- Переходы статусов заказ-наряда — только через доменный метод/сервис, каждый
  переход пишется в `work_order_status_history`.

## Persistence

- Схемой владеет Flyway, `ddl-auto: validate`. Применённые миграции не редактируются —
  только новая `V{n}__описание.sql`.
- Целостность — в БД: `NOT NULL`, `UNIQUE`, `CHECK` для перечислений, FK + индекс на FK.
- id: `bigint generated always as identity`.
- Сущности: без `@Data`; `@Getter`/`@Setter`, `protected` конструктор без аргументов;
  все `@ManyToOne`/`@OneToOne` — `LAZY`; `@Enumerated(EnumType.STRING)`;
  `equals`/`hashCode` — по id с учётом прокси Hibernate (или не переопределяются).
- Деньги — `BigDecimal` / `numeric`. Пароли — только хеш.
- Конкурентно редактируемые агрегаты (заказ-наряд) — оптимистическая блокировка `@Version`.
- Следить за N+1: связи грузим явно (`JOIN FETCH` / `@EntityGraph`), когда они нужны.

## Тесты

- Интеграционные — Testcontainers (PostgreSQL 17); конфигурация контейнера в одном
  месте, контейнер переиспользуется между тестовыми классами.
- Срезы: `@DataJpaTest` для репозиториев, `@WebMvcTest` для контроллеров,
  unit-тесты для бизнес-правил (переходы статусов).
- `./mvnw verify` проходит локально и в CI.

## Конфигурация и безопасность

- Секреты — только через переменные окружения / `.env` (в `.gitignore`),
  в репозитории — `.env.example`.
- В логах нет паролей, токенов и персональных данных клиентов.
- `show-sql` — только в dev-профиле.

## Ревью PR (как делает Claude)

- Уровень — senior в продуктовой команде: корректность, данные, транзакции,
  контракт API, тесты, безопасность; стиль — в последнюю очередь.
- Пометки: 🔴 блокер · 🟡 стоит исправить · 🟢 мелочь · 📚 спросят на собесе.
- Не предлагать абстракции «на вырост», которых не требует текущая задача.
